# Studies

Real-data results: estimates for actual traits, from public GWAS.

Separate from `benchmarks/` because benchmarks measure the estimator against
simulated known truth and get regenerated every release, whereas these are
estimates whose truth is unknown. The practical difference showed up
immediately: 0.3.6 reseeded the LD-screen masks and the LDL x CAD estimate
moved from `rg` 0.2856 to 0.2658. Routine for a benchmark; worth noticing for
a result.

## Layout

```
studies/
  _lib/
    traits.toml      files, column layouts, N, ancestry, known defects
    datasets.md      sources tried and what is wrong with them
    methods.tex      the Methods section both reports share
  <study>/
    README.md        question, traits, result, caveats
    REPORT.tex       hand-written; \input's sections/ and ../_lib/methods.tex
    REPORT.pdf
    sections/*.tex
    figures.py       redraws figures/ from results/estimates.csv
    figures/*.pdf
    results/
      estimates.csv  overwritten on re-run; version and platform are columns
      provenance.json
```

Results are overwritten; git keeps the history. Every row carries the bipred
version and platform that produced it.

The report is a document, edited directly. Only the figures are generated, and
`figures.py` reads only `results/estimates.csv` -- never the summary
statistics -- so both rebuild for someone who does not have 9 GB of GWAS files:

```bash
cd studies/<study> && python figures.py && pdflatex REPORT.tex
```

`_lib/methods.tex` is shared because the estimator does not differ between
studies. Each report supplies its own "This analysis" subsection after it.

## No run.py yet

These results were generated by `benchmarks/real_ldl_cad.py` and by drivers
that monkeypatch `benchmarks/qc_factorial.py`'s module globals -- `TRAITS`,
`PAIRS`, `ARMS`, `validate_inputs`, `read_aligned`. A `run.py` that reproduced
that patching would entrench it, so two things still want fixing:

1. `TRAITS` should read [`_lib/traits.toml`](_lib/traits.toml) rather than
   being a literal, with column layouts as named vintages -- public releases
   use at least three, and several override a column or two on top of one.
2. Dataset quirks (`effect_is_odds_ratio`, `frequency_is_maf`,
   `no_allele_frequency`) should be declared flags applied once, not
   corrections patched in by each caller.

Two others are now fixed. `qc_factorial.py` has a CLI: `--out` so a run names
its own file instead of overwriting the committed artifact, `--rounds`, and
`--chi2-cap`. And its checksum set is derived from the traits in `PAIRS`
rather than a hardcoded list, so narrowing `TRAITS` no longer raises
`KeyError: 'LDL'`. A driver can now pass arguments instead of patching
globals:

```python
import qc_factorial as Q
Q.TRAITS = {**Q.TRAITS, **NEW}
Q.PAIRS = [...]
Q.main(Q.parse_args(["--out", "mine.csv", "--chi2-cap", "ldsc"]))
```

`real_data_inputs.py` -- manifest validation, clean-source gate, provenance
sidecars -- needs no change and should be reused as is.
