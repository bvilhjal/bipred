# Studies

Biological results: estimates about traits, not measurements of the estimator.

`benchmarks/` characterises bipred against known truth on simulated data. The
work here does something different — it produces estimates whose truth is
unknown, from public data with real defects, and those two things need
different handling:

| | `benchmarks/` | `studies/` |
|---|---|---|
| the claim is about | the estimator | the world |
| truth | known, simulated | unknown |
| on a release | regenerate | re-run and note the version |
| a wrong number means | a code bug | possibly a *data* problem |
| needs | pass/fail | uncertainty, controls, caveats |

The distinction is not academic. bipred 0.3.6 reseeded the LD-consistency
screen's masks, and the LDL x CAD estimate moved from `rg` 0.2856 to 0.2658.
Under a benchmark contract that is routine regeneration; read as a biological
result it is an estimate changing because of an implementation refactor. The
split exists so that difference is visible rather than silent.

## Layout

```
studies/
  _lib/
    traits.toml      trait registry: files, columns, N, ancestry, known defects
    datasets.md      sources tried and what is wrong with them
  <study>/
    README.md        question, design, caveats
    config.toml      traits, arm, anchors, controls
    report.py        renders REPORT.md from results/ alone
    REPORT.md        readable with no data present
    results/
      estimates.csv  overwritten on re-run; version and platform are columns
      provenance.json
```

**`run.py` is not here yet.** The results below were generated by
`benchmarks/real_ldl_cad.py` and by drivers that monkeypatch
`benchmarks/qc_factorial.py`'s module globals -- which is precisely the
coupling this layout exists to remove. See
[`_lib/MIGRATION.md`](_lib/MIGRATION.md) for what has to move first. Shipping a
`run.py` that reproduces that patching would entrench it.

Results are overwritten rather than accumulated: git history is the record, and
every row carries the code version and platform that produced it, so a
re-run remains attributable after the fact.

`report.py` must not read the summary statistics. If rendering the report needs
9 GB of GWAS files, the study is not self-contained and nobody else can read it.

## Adding a study

1. State the question in `README.md` before any results exist.
2. Register every dataset in [`_lib/traits.toml`](_lib/traits.toml) with
   accession, N, ancestry and known defects.
3. Declare calibration anchors and null controls in `config.toml`. Overlap
   statistics are uninterpretable without them — see the `oligogenic-overlap`
   report for what that costs when they are missing.
4. Bind caveats to the numbers they qualify. A genetic correlation reported
   without its architecture caveat will be quoted without it.
5. Record rejected datasets. A source that cannot be used is a finding, and
   re-deriving it costs hours.
